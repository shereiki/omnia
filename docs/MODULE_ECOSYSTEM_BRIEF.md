# OMNIA — Fix the Module Ecosystem and Repetitive Branding

These two issues must be corrected in the current build. Do not redesign the entire website.

## 1. STOP presenting Omnia Modules as a fixed catalog

The current Modules presentation repeatedly shows the same handful of named Modules. It makes visitors think Omnia has three or four prebuilt products, and those are their choices.

**This fundamentally misrepresents Omnia.**

Omnia Modules are an expandable ecosystem of capabilities. They can be:

- Reusable capabilities already developed for the Omnia ecosystem.
- Existing Modules customized for a particular organization.
- Completely new Modules engineered for requirements that existing capabilities don't address.
- Combinations of Modules that create entirely new functionality.

A Module can support integrations, extensions inside existing applications, automation, custom services, and the logic powering new frontends and customer experiences.

The internal types are Connectors, Extensions, Automations, and Custom Services. These are broad classifications, **not four individual Modules**.

### Replace the current Module presentation

Remove the repetitive named-card composition, particularly the cards labeled "Knowledge at hand," "Current records," "Coordinated actions," and "Request review."

Do not simply rename these cards.

Build a visually expandable Module ecosystem.

**Exact interaction:**

1. Start with a small collection of visually distinct, illustrative capabilities surrounding the established OS.
2. As the exploration progresses, additional Module elements become available and join the environment.
3. Show that some capabilities are reused, others adapted, and another created specifically for the implementation.
4. Reveal additional potential Module positions extending beyond the initial arrangement. The visual must not imply the displayed examples are an exhaustive catalog.
5. Demonstrate how several Modules combine to power a recognizable output, such as an Omnia-built interface or enhanced third-party application.

Do not portray this as a marketplace with hundreds of released plugins. The project is prelaunch.

Use the existing design system, but create a real visual language for Modules. Small, elegant, modular components are preferable to massive repetitive feature cards.

Do not represent every Module with a miniature Omnia logo.

Do not use arbitrary labels or generic code icons as placeholders.

### Exact copy

**Heading:**
An ecosystem that grows with you.

**Supporting copy:**
"Omnia Modules expand what Omnia OS can do. Reuse existing capabilities, adapt them to your environment, or introduce something entirely new.

From integrations and automations to custom services and complete digital experiences, Modules can be combined to create technology designed around your needs."

**Supporting line:**
"Not limited to a predefined catalog."

Do not add a list of supposedly prebuilt Modules or imply specific integrations are already released.

## 2. STOP repeating the Omnia logo on mint-green platforms

The website keeps using the exact same visual formula:

- Mint-green oval or surface.
- Large dimensional Omnia logo.
- "Omnia OS" written beneath it.
- Floating cards surrounding it.

This is repeated so frequently that the visual identity becomes monotonous and the illustrations begin to look identical.

**Remove this repeated composition.**

### New visual rule

The dimensional Omnia logo is a brand anchor, not a universal illustration component.

Use it prominently in the hero or primary OS reveal.

In subsequent technical visualizations, represent the technology through its actual conceptual structure:

- Omnia OS: an identifiable, consistent foundation.
- Modules: distinct modular capability elements.
- Native Intelligence: an integrated system layer with contextual knowledge, configurable agents, and controlled capabilities.
- Solutions: interfaces, applications, services, and experiences powered by those elements.

Do not place another enormous Omnia logo in the center of every illustration.

Do not use large mint ovals as the default container for the OS.

Mint should remain an accent color for emphasis, active functionality, and meaningful interactions—not a background slab repeated in every section.

### Specifically fix

- The main OS explorer.
- The cumulative Module visualization.
- The internal-agent illustration.
- The customer-agent illustration.
- Any repeated mint platform with a floating logo.
- Logo and label overlaps caused by the existing composition.

Retain the actual Omnia logo and its canonical color arrangement. Do not redesign the mark.

The visual style should remain unmistakably Omnia even when the logo isn't physically present.

## 3. Give each visualization a different purpose

**OS introduction:** Establish the foundation, using the main dimensional logo.

**Modules exploration:** Demonstrate an expanding, adaptable ecosystem. Prioritize modularity and growth, not a giant logo.

**Native Intelligence:** Demonstrate contextual knowledge, agent configuration, permitted access, and actions. No mint platform or central logo necessary.

**Solutions / frontend experience:** Show a sophisticated, believable interface that Omnia can build or extend. Let the software experience itself carry the visual.

These visuals should feel like different chapters of the same design system, not the same diagram rearranged four times.

## 4. Preserve the pinned scrolling requirement

The five-stage OS exploration must remain pinned while scrolling advances the stages, then release after Stage 5. Reverse scrolling must work.

Any Module animation must synchronize with that scroll-controlled experience.

Do not replace the scroll interaction or introduce a new navigation approach.

## 5. Visual quality requirements

Before completion, inspect actual browser screenshots of every relevant section.

Confirm:

- The Modules section does not resemble a fixed product catalog.
- The displayed examples do not imply they are the only available or prebuilt capabilities.
- The Module ecosystem visibly supports new and custom capabilities.
- The Omnia logo is not repeated as the dominant visual throughout the website.
- Mint-green ovals and platforms are no longer the default visualization.
- Every illustration has a distinct, clear purpose.
- No collisions, overlaps, disconnected connector lines, or decorative filler.
- The current premium visual design is preserved.

**Do not solve these problems by changing text alone. They are principally visual-design and product-representation problems.**

Implement these corrections directly and verify the rendered results.
